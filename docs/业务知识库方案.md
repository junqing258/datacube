# DataCube 业务知识库方案

本文是供产品和工程评审的首版方案。目标是让外部 AI Agent 从一个业务问题出发，找到已发布的口径、对应的数据模型和可用的关联，执行授权范围内的查询，并给出可追溯的答案。业务人员可在 DataCube 查看同一份知识及其历史版本。

目前已有销售经营、多仓库存、加工损耗和直播经营四个 Markdown 主题，以及数据集、字段、指标、数据集关联、知识授权和图表引用的 Prisma 模型。当前 Web 知识页读取原型构建产物。首版将这些内容接入同一个服务端读取模块，由 Web、MCP 和平台 API 使用。 [产品方案](产品方案.md#7-语义与可信度) · [数据库设计](数据库设计.md) · [知识页实现](../apps/web/src/pages/KnowledgePage.tsx)

## 知识模型

知识主题按业务问题组织，一个主题可以引用多个指标和数据集，同一个指标也可以出现在多个主题中。主题维护业务解释和用法，指标维护正式计算定义，数据集及字段维护读取契约和物理映射。

| 对象     | 需要记录的内容                                                                                                            | 首版存放位置                                                                                          |
| -------- | ------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 知识主题 | 业务范围、常用术语及别名、业务流程、适用规则、常见问题和反例、负责人、依赖的指标和数据集                                  | `docs/knowledge/<topic>/v<N>.md`。正文为 Markdown，结构化元数据记录标题、摘要、别名、负责人及目录引用 |
| 数据集   | 来源系统、表或 API、行粒度、唯一键、覆盖范围、主时间字段、刷新方式。参数化 API 还需声明参数、返回粒度、支持维度和聚合限制 | 复用 `DataConnection`、`Dataset` 与读取契约                                                           |
| 字段     | 业务含义、类型、单位、枚举、别名、敏感标记和源字段映射                                                                    | 复用 `DatasetField` 与数据集契约                                                                      |
| 指标     | 业务含义、公式、过滤条件、时间归属、单位、可用维度、跨维度和跨时间的聚合规则                                              | 复用 `Metric`。从绑定版本的结构化定义返回计算规则，Markdown 补充背景和实例                            |
| 业务关联 | 对象之间如何关联、业务键、匹配范围、例外情况，以及相应的查询能力                                                          | 在主题中说明，并引用关联定义、预整理数据集或对账查询。尚无可执行映射时标记为仅说明                    |
| 查询关联 | 两端数据集、键对、方向、基数，以及先聚合到什么粒度、如何保留未匹配记录                                                    | 同连接的关联复用 `DatasetJoin`。预聚合、额外过滤及未匹配处理由对应指标或查询定义指定                  |

主题引用使用稳定的目录标识，发布时在目标空间解析到实际对象。数据集键在连接内唯一，指标键在数据集内唯一，引用须带上所属连接与数据集信息。物理表名和字段映射以数据集契约为准，业务术语可随主题解释。 [Prisma 模型](../apps/server/prisma/schema.prisma)

### 业务关联与查询关联

**订单与退款。** 一笔订单可有多笔退款。计算净销售额时，以订单为查询入口，先过滤并汇总截至快照时点的成功退款，再按已验证的订单键关联回订单，保留无退款订单。若逐条关联退款后直接汇总支付金额，同一笔订单的支付金额会被重复计入。上线前需要用真实商城契约确认订单键与退款归属键。 [销售经营](knowledge/sales/v1.md#数据映射)

**ERP 加工完工单与 WMS 入库单。** 两个来源都可能在同一仓库和加工批次下有多条明细。先统一重量单位，再分别汇总到「仓库 × 加工批次」，然后计算入库差额。首版通过预整理数据集提供查询能力，保留两侧数据时间。缺失一侧的记录标为待核对。`DatasetJoin` 继续限定在同一连接。 [加工损耗](knowledge/processing/v1.md#数据映射) · [跨源设计](产品方案.md#跨源边界)

## Agent 调用与 Web 阅读

首版知识工具提供两个只读操作。搜索先用标题、指标名、别名、常见问法和摘要做匹配。候选结果只带用于选择口径的信息，随后按需读取详情。

| 操作               | 输入                             | 返回                                                                                                                   |
| ------------------ | -------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `search_knowledge` | 问题或关键词，可选主题与对象类型 | 已授权的候选主题和指标，含对象标识、主题标识、主题版本、摘要和引用链接                                                 |
| `get_knowledge`    | 对象标识、主题标识，可选主题版本 | 主题正文或指标详情，以及可见的数据集、字段、关系、适用维度、限制和出处。省略版本时使用当前发布版本，返回实际选中的版本 |

同一指标出现在多个主题时，主题标识和版本确定本次采用的发布定义。搜索返回的引用可直接传给详情读取，避免两次调用之间恰好发布新版本。搜索无结果时返回空列表。对于已授权的主题和对象，指定版本缺失时返回明确状态。未授权对象与未知对象使用统一的对外响应。遇到多个合理口径，Agent 要说明差异并澄清。请求维度超出接口能力，或查询映射尚未确认时，返回对应限制。

Agent 读取口径后，使用平台的只读查询能力，传入已选指标、主题版本和必要参数。执行层重新验证当前数据权限、维度、时间范围与关联能力，并把实际采用的口径、数据源、统计区间和数据时点记录到查询执行记录。Skill 维护检索、澄清、查询及引用的操作流程，企业口径通过平台实时读取。 [MCP 与 Skill](产品方案.md#5-mcpskill-与平台-api) · [查询追溯模型](../apps/server/prisma/schema.prisma#L383)

Web 沿用「业务知识」入口和 `/knowledge/<topic>/v<N>` 链接，提供已授权的主题列表、版本切换、原文下载和关联对象。图表跳转使用绑定版本。正式内容通过服务端按权限读取，页面 HTML 和原文下载使用同样的权限规则。

## 维护、发布与权限

### 维护与版本

首版建议由业务负责人确认口径和样例，开发者维护字段映射与可执行规则，经 Git 评审后发布。部署时生成服务端发布清单，将主题版本绑定到当时的指标定义、规则、字段映射和关联定义，留存可读取的不可变快照。后续数据目录更新通过重新发布生效，旧图表仍可读取当时绑定的定义。

发布流程包括三项检查。

1. **核对引用。** 校验主题标识与版本、元数据格式、引用对象的空间归属、字段存在性和关联约束。确认执行所需的规则已经录入结构化定义。
2. **核对样例。** 使用固定测试数据或同一数据快照，对照预期金额、行数、聚合粒度和未匹配情况。业务负责人确认含义，开发者确认执行结果。
3. **核对版本影响。** 列出受影响的图表，保留旧主题和定义。计算规则、映射或已发布正文要改动时发布新版本。校验通过后整体切换发布版本，失败时继续使用上一份。若历史映射因源结构变化已无法执行，仍提供已授权的历史说明，并提示查询不可执行。

口径版本和数据时点分别记录。固定口径版本用于还原定义。复现当时的数值还要有原数据快照或留存结果，尤其是历史期间会被晚到退款改写的指标。 [图表口径引用与执行记录](数据库设计.md#实体关系)

### 权限

- **主题。** 按当前空间成员和 `KnowledgeGrant` 判断主题可见性。Agent 的有效权限同时受 API Key 授权范围限制。
- **映射。** 独立检查数据集与字段权限，应用到搜索摘要、详情、关联名称和链接。正文中直接出现的物理映射会随主题可见，含敏感映射的内容按受众发布，或通过受权限控制的目录引用展示。
- **执行。** 知识读取与数据查询分别授权。保存的链接、查询结果和缓存按访问时的权限检查。缓存按版本和权限范围隔离，成员或 Key 权限收回后即失效。

## 首版场景与验收

首版以「销售经营 → 净销售额」交付从搜索、读取到只读查询和结果引用的一条完整路径。加工损耗用于验证跨源业务关联的表达。其他主题可逐步接入同一目录。

| 场景                           | 验收结果                                                                                                                                                                                            |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 搜索「本月净销售额」或指标别名 | 找到销售经营和净销售额，返回明确版本。Web 与 MCP 读取同版本时使用同一口径和引用                                                                                                                     |
| 净销售额按渠道拆分             | 使用北京时间的原订单支付日和原订单渠道。按 11 月 1–25 日及 11 月 26 日结束后的退款快照计算，支付 1,600 元，退款 170 元，净销售额 1,430 元。增加一单多笔退款和无退款订单的用例，确认支付金额各计一次 |
| 查看加工损耗与入库差额         | 可发现 ERP 和 WMS 的批次关联，识别预整理数据集和两侧数据时点。样例 `JG-1125-02` 返回加工损耗率 11% 和入库差额 32 kg                                                                                 |
| 版本切换及历史引用             | 新查询默认读取新发布版本，旧图表仍定位到原文和当时的定义。指定缺失版本时提示缺失。发布校验失败时，现有服务继续读取上一份发布内容                                                                    |
| 数据维度或映射不可用           | 返回结构化限制，引导 Agent 向用户澄清或说明当前数据能力                                                                                                                                             |
| 权限收回或越权访问             | 搜索、详情、原文下载、历史链接及缓存均遵循当前权限。仅获主题授权的用户只能看到该主题面向其受众的正文和已授权的目录信息                                                                              |

样例口径和数值见 [销售经营](knowledge/sales/v1.md#常见问题) 与 [加工损耗](knowledge/processing/v1.md#常见问题)。

## 待确认事项

- **维护角色。** 若业务同事需要独立提交修改，将 Web 草稿、复核和发布纳入首版。若由业务和开发共同走 Git 评审，首版保持只读知识页。
- **真实数据映射。** 确认商城订单与退款的唯一键、状态、时间字段和可对账样本，以及 ERP 与 WMS 的批次键、单位和预整理数据的生产方式。
- **首个外部客户端。** 用实际试点客户端确认 MCP 接入方式、鉴权配置和工具返回格式。
