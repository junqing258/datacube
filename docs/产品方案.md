# DataCube：面向外部 Agent 的企业 BI 平台方案

版本：v0.6 · 2026-11-25 · 需求与原型讨论稿

## 1. 已确认的产品方向

DataCube 面向企业内部业务人员，前期由开发者辅助接入数据与维护业务定义。数据源首先支持 MySQL、PostgreSQL、内部业务 API 和自定义转换 API。

平台页面提供多看板、图表展示、业务知识与配置管理，不提供独立数据探索或 SQL 编辑页面。**页面不设置 AI 会话入口，不内置对话工作台。** 自然语言查数、自动生成看板和主动深入分析，由用户在外部 AI 客户端或 Agent 中发起，通过 MCP 或 Skill 使用平台能力。

产品的 AI Native 特征体现在可供 Agent 使用的语义、查询与内容管理能力，而非网页中的聊天组件。

### 经营试点

蛋鲜森招聘页列出的业务包括双仓加工、电商销售和新媒体直播。岗位要求衔接小程序、商城、ERP、WMS 及平台接口，统一销售、库存、加工损耗和直播营销指标，并评估 AI 应用的准确性、效率和成本。[蛋鲜森 AI 技术负责人职位](https://www.zhipin.com/job_detail/f5e9ed6265b72c4b0nxy3N-8EltS.html)

将该场景用作 DataCube 的首个行业试点。看板、指标与异常为演示设计，实际仓库名称、系统结构、业务口径和阈值以现场核对为准。

| 看板 | 日常问题 | 首批数据和口径 |
| --- | --- | --- |
| 电商销售总览 | 哪个渠道贡献销售额，退款如何影响净销售额？ | 小程序与平台订单、支付、退款。按来源和平台订单号去重，明确退款归属和截至时间 |
| 多仓库存与缺货 | 哪个仓库需要补货或优先处理临期批次？ | WMS 的仓库、SKU、批次及库存快照。标注时间和单位，按仓查看临期及缺货 |
| 加工损耗与入库核对 | 哪个加工批次应复核，完工与入库差多少？ | ERP 投料、报损、合格产出及 WMS 已确认入库。按仓库加批次分别聚合后核对 |
| 直播经营复盘 | 哪场直播成交、退款表现如何？ | 平台场次与订单、商城退款。只展示已匹配场次的订单，单列无法归因数量，成本齐备后再计算利润 |

首个演示路径从首页的加工异常出发。进入加工看板后按仓筛选，打开批次核对 ERP 完工单与 WMS 入库记录，再查看损耗口径。实际损耗和入库差额分别跟踪。差额可能来自入库状态、同步时差、单位换算或现场记录，确认原因由运营人员复核。

数据接入先用代表样例核对订单号、仓库、SKU、批次、场次及计量单位。不同系统的订单号有冲突时，使用来源与订单号的组合标识。加工和入库有多条明细时先分别聚合，避免关联放大。快照按时间点比较，源系统按不同频率刷新时展示各自数据时点。

外部 AI 通过现有 MCP / Skill 使用已发布口径、查询经营数据并返回结果链接。试点先验证常见问题能否对齐 ERP/WMS 基准，以及异常定位耗时、人工复核次数和每次分析成本。小程序商品交易、库存写入、客服辅助和内容生成作为招聘背景中的其他系统需求，DataCube 本轮覆盖其经营数据接口和分析场景。

## 2. 角色与职责

| 角色 | 任务 |
| --- | --- |
| 业务人员 | 浏览与筛选看板，管理内容，在外部 AI 工具发起分析 |
| 开发者／数据维护人员 | 配置连接、API 契约、字段含义、指标与关联 |
| 管理员 | 管理成员、空间、数据权限、外部接入权限与审计 |

## 3. 核心工作流

### 页面内 BI 操作

打开看板列表 → 搜索或收藏 → 进入独立看板 → 筛选与刷新 → 添加已有图表、编辑名称或复制看板。新查询与新图表由外部 MCP / Skill 创建，业务知识页提供口径查阅。

看板支持布局调整、全局筛选、刷新和企业内部分享。接收者仍需具备底层数据权限。

### 外部自然语言查数

1. 用户在外部 AI 客户端提出问题。
2. Agent 通过 MCP 或平台 API 读取已授权、随部署生效的 Markdown 业务知识。
3. Agent 澄清关键口径，形成计划并调用只读查询工具。
4. 平台执行权限、能力和预算校验，返回结果、实际时间范围、来源与执行记录。
5. 外部工具解释结果，按需创建图表并返回 DataCube 页面链接。

### 外部自动生成看板

用户在外部工具描述目标 → Agent 复用已有指标并生成图表 → 创建看板草稿 → 返回平台链接 → 用户在页面检查、编辑并保存。

内容写入需具备明确授权。部分图表失败时保留成功结果，失败卡片不以零值替代。

### 外部主动深入分析

Agent 在用户授权范围内逐步查询趋势、维度与指标变化。平台对每次调用校验权限，并限制次数、时长、行数与并发。Agent 区分数据事实、可能解释和待验证事项。首版建议仅覆盖用户触发的深入分析，后台定期监测待确认。

## 4. 页面与原型

主导航：**首页、看板、业务知识、数据接入、AI接入**。配置页面按权限可见。

| 页面 | 能力 |
| --- | --- |
| 首页 | 收藏看板、团队看板、数据资产入口，无 AI 输入框 |
| 看板列表与详情 | 搜索、收藏、新建、复制、归档、切换、图表布局、筛选、刷新与分享 |
| 业务知识 | 按主题阅读 Markdown，查看文档版本和原文，从看板跳转至引用版本 |
| 数据接入 | MySQL、PostgreSQL、API 配置、连接测试和预览 |
| AI接入 | MCP / Skill 接入方式、服务地址、接入步骤、能力说明、API Key 生命周期与调用记录 |

首页原型提供三种信息结构：A 资产导航优先、B 经营概览优先、C 团队资产优先。三种均不包含 AI 会话。

### 多看板结构与操作

采用“空间 → 多个看板 → 多个图表卡片”结构。每个看板有稳定 ID、独立链接、名称、说明、来源、版本、布局、筛选默认值、刷新策略和访问范围。

- 列表支持名称搜索、收藏视图、有效看板与归档视图。
- 新建默认空白，可添加已有图表；外部 Agent 可直接创建带内容的看板。
- 复制生成新 ID，复制布局与筛选；共享图表定义继续引用，后续卡片增删互不影响。
- 归档保留内容并从默认列表移除，可恢复。归档看板不允许编辑。
- 筛选和展示配置归属于当前看板，不影响其他看板。
- 图表定义保存数据查询和默认展示；卡片保存图表引用、位置、尺寸、标题覆盖和筛选映射。
- 移除卡片不删除共享图表。修改共享定义需提示引用范围；独立修改时先复制图表。
- 复杂看板内标签页、文件夹和后台定时刷新交互后续补充。

MCP / Skill 支持按空间查找看板、读取详情、按 ID 添加或移除卡片、更新布局及筛选。更新请求携带预期版本；版本不符返回冲突，Agent 重新读取，避免覆盖他人变更。重复创建和重试应通过幂等键去重。

原型已演示多看板列表、独立详情、新建、复制、收藏、归档与恢复、切换、添加和移除共享图表、改名。筛选示例只保存独立时间选择；真实查询、权限、布局拖拽与持久化尚未实现。

## 5. MCP、Skill 与平台 API

### MCP

平台提供面向外部客户端的 MCP 服务。建议能力包括：

- 按业务主题列出或读取已授权的 Markdown 文档，返回主题标识、文档版本与正文。支持读取数据集、图表与看板。
- 执行只读结构化查询，或在权限允许时执行校验后的 SQL。
- 查询任务状态、获取结果、取消任务。
- 创建图表和看板草稿，返回可访问的页面链接。

工具名称、传输方式和客户端适配细节在工程设计阶段确定。原型中的地址与连接 JSON 仅为示意，不代表已实现服务。

### Skill

Skill 是供外部 Agent 使用的操作指南，描述业务发现、口径澄清、查询、验证与保存流程。执行通过 MCP 或平台 API 完成，不能绕过平台权限。Skill 按需读取平台提供的 Markdown 文档，凭据通过客户端配置。

若采用直接平台 API 调用，API 与 MCP 必须共享授权、限额和执行层。首版 Skill 包和安装方式待实际 Agent 环境确认后实现。

### API Key 配置

这里的 API Key 是 **DataCube 平台访问凭据**，不是模型供应商密钥。模型与会话由外部工具管理，平台首版不需要模型供应商配置页。

创建时配置：名称、所属空间、授权范围、有效期。授权范围建议至少拆分为目录读取、查询执行、内容读取、图表创建、看板创建；原型简化为“只读查询”和“查询 + 创建图表与看板”。

- 有效权限为持有人权限与 Key 授权范围的交集。
- 完整 Key 仅创建时展示一次；列表显示掩码、创建时间、到期时间、最后使用时间与状态。
- 提供复制、撤销和轮换流程；轮换通过创建新 Key、切换客户端、撤销旧 Key 完成。
- 后端仅保存验证所需的不可逆摘要，日志与页面不回显完整密钥。
- Key 过期、撤销、成员停用或权限收回后，相应访问应失效。
- 记录 Key 标识、操作者、工具、数据范围、执行状态与耗时，禁止记录鉴权 Header。
- 创建的图表和看板保留创建者及接入来源。

## 6. 数据源设计

### MySQL / PostgreSQL

支持连接配置、TLS、指定库表范围、元数据读取、数据预览和只读查询。支持同一连接内关联；关联基数和业务粒度必须维护，避免重复汇总。

### 明细数据集 API

配置 URL、方法、鉴权、参数、数据路径、分页、字段映射、唯一键和刷新周期。建议同步为平台数据集，首版优先全量刷新，成功后切换版本，失败保留上一版并显示过期状态。增量与删除同步待实际接口契约确认。

### 参数化查询 API

声明参数类型、默认值、枚举、返回结构、结果粒度、单位、支持的维度与聚合限制。例如库存周转 API 已返回比率时，不允许直接平均结果。

平台根据契约校验调用。无支持维度时明确返回能力不足，不允许 Agent 猜测拆分结果。

### 跨源边界

首版建议支持同一看板展示多个数据源的独立图表；临时跨库及数据库与 API 关联后置。必要的整合可由自定义转换 API 或预整理数据集提供。跨源看板分别显示数据时间。

## 7. 语义与可信度

数据集维护粒度、业务描述、时间字段与负责人；字段维护别名、单位、枚举和敏感标记；指标维护公式、过滤条件、时间规则、可用维度与聚合规则。

### Markdown 业务知识

以仓库内的 `knowledge/<主题标识>/v<编号>.md` 为唯一维护来源。销售经营、多仓库存、加工损耗和直播经营各有文档。每份文档先写业务范围和指标口径，再提供适用规则、问题示例和数据映射。指标计算仍由查询服务、SQL 或 API 实现，Markdown 提供解释和使用依据。

负责人和开发者通过现有仓库流程修改文档并随应用部署。影响计算口径时增加新的版本文件，保留被图表引用的旧版。Git 记录文档变更。页面仅提供列表、正文阅读、版本选择和原文链接。

图表保存主题标识与确切版本，点击口径可回到该版本。版本缺失显示明确提示。知识列表打开已部署的最新版本。后续 MCP / API 使用同一套文档，按调用者权限列出主题和读取版本，Skill 指引外部工具读取。首版知识功能仅提供读取。

静态原型将 Markdown 转成只读页面所需的内容文件，便于直接打开本地 HTML。真实接入、权限与 MCP 读取在工程实现阶段交付。

[业务知识维护产品调研](research/业务知识维护产品调研.md)

查询结果包含数据来源、口径、筛选条件、实际日期范围、数据更新时间、执行时间和查询依据。空数据、结果截断、缺失、失败与权限不足分别返回结构化状态。

“本月至今对比上月同期”与“完整上月”必须区分。不同维度的重叠贡献不可累加；相关性不能直接表述为因果关系。这些规则同时进入 Skill 指南与工具结果说明。

## 8. 核心对象与技术边界

核心对象：空间、成员、数据连接、数据集、Markdown 知识文档及版本、查询定义、图表、看板、执行记录、API Key。

页面与外部工具共用应用服务、业务语义、权限和查询执行层。建议采用模块化单体，长任务使用独立执行进程，不预先锁定语言和框架。

```text
Web BI 页面 ──────────┐
外部 Agent → MCP ─────┼→ 认证与权限 → 语义 / 查询 / 内容服务
外部 Agent + Skill   │                    ↓
           → API ────┘          数据库连接器 / API 连接器
```

平台不保存外部完整聊天记录，也不承担模型编排；保留平台实际收到的调用、执行与内容变更记录。外部 Agent 的推理预算由外部工具管理，平台负责自身查询与 API 调用限额。

## 9. 权限与内部部署

- 内容权限与数据权限分别校验，分享和创建内容不扩大数据访问范围。
- Web、MCP 与 API 统一授权，缓存按权限范围隔离。
- 首版支持空间、数据集和字段级权限；行级隔离是否为上线必需项待确认。
- 数据连接凭据保存在后端，数据源凭据与平台 API Key 分开管理。
- 外部 AI 客户端接收的数据遵循调用者权限；允许哪些客户端接入和哪些数据可出域由企业部署策略决定。
- 后台同步使用共享服务账号时，需单独配置同步后数据集的访问范围。

## 10. 交付阶段

### 第一阶段：交互原型

验证多看板管理、双仓加工异常定位、Markdown 业务知识读取，以及 AI接入与 Key 创建、复制、撤销流程。全部使用固定演示数据，不运行模型、不建立真实连接、不生成有效 Key。

### 第二阶段：端到端最小实现

实现数据库接入、Markdown 业务知识读取、只读查询、图表与看板；实现 API Key 鉴权和首批 MCP 工具，从外部客户端完成查数与创建看板，并提供平台链接。

### 第三阶段：首版完善

根据真实接口补齐两类 API 数据源、Skill 包、长任务管理、调用审计和限额；验证深入分析任务中的正确性与权限。阶段工期在技术栈、接口样例和数据规模明确后估算。

## 11. 验收标准

- 页面没有 AI 会话入口和独立数据探索页面，业务人员可管理多个看板并筛选查看结果。
- 页面能读取仓库中随部署生效的 Markdown 知识。看板跳转打开绑定版本。指定版本缺失时显示提示。
- 外部客户端可读取授权语义、运行查询、创建图表与看板并打开页面成果。
- 查询的时间、口径、筛选、聚合及数值与人工核对的 SQL / API 基准一致。
- API Key 创建时展示一次；过期、撤销及权限收回均限制后续访问。
- 只读 Key 不能创建内容，任何 Key 都不能超越持有人数据权限。
- Web、MCP、API、分享和缓存均不返回越权数据。
- 查询失败、空数据、超时和部分成功状态可区分，结果可追溯。

## 12. 待确认事项

1. 首批外部客户端或 Agent 环境，以及采用 MCP、Skill 或两者同时交付。
2. 是否需要个人 Key 与服务账号 Key 两类凭据。
3. 双仓试点的真实指标、系统字段、接口示例和对账责任人。
4. 行级权限、跨源关联是否为首版必需。
5. 数据规模、并发、刷新周期和查询响应目标。
6. 主动分析是否包括后台定期运行，目前建议后置。
