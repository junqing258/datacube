# 多源图表设计

## 目标

支持一张图同时展示来自多个数据库、多个 API，或数据库与 API 混合的指标。首版通过定时刷新生成一个供图表查询的数据集。看板中各自使用不同来源的独立图表可以继续分别绑定查询。

## 现有模型与扩展

当前 Prisma 数据模型中的链路为 `Chart → QueryDefinition → Dataset → DataConnection`。每张图绑定一个查询，每个数据集绑定一个连接。`DatasetJoin` 通过组合外键限制在同一个连接内。多源输入在刷新阶段合并为一个输出数据集，图表沿用该模型关系查询。授权、刷新任务和快照读写服务随首版实现。[数据库设计](./数据库设计.md) · [Prisma schema](../apps/server/prisma/schema.prisma)

| 对象 | 拟议设计 |
| --- | --- |
| 输入数据集 | 复用 `Dataset` 和 `DataConnection`。数据库输入配置表、字段与可用筛选。API 输入配置分页、请求参数和响应字段映射。凭据由后端通过 `secretRef` 解析。 |
| 输出数据集 | 为 `Dataset.kind` 增加 `derived_snapshot`，输出记录当前合并定义版本，绑定平台管理的快照存储连接。对应增加连接类型和读取实现。 |
| 输入依赖 | 新增 `DatasetInput`，记录 `spaceId`、输出数据集、输入数据集和输入别名。两个数据集分别用 `[spaceId, datasetId]` 约束，别名在输出内唯一。首版仅接收直接来源。 |
| 合并契约 | 在输出数据集的 `contract` 中配置输入字段、筛选与聚合关系、合并键、输出字段映射和派生指标。服务端保存前校验引用、类型及输出粒度。 |
| 快照与血缘 | 复用 `DatasetSnapshot` 和 `ActiveDatasetSnapshot`。为快照补充启动序号和血缘元数据，记录不可变的合并定义版本、各输入数据集标识、数据覆盖水位、取数范围，以及本快照实际读取的源字段标识。字段依赖涵盖输出映射、筛选、分组、合并键、去重和派生计算。图表执行时在 `QueryExecution.provenance` 中记录实际读取的快照及其来源。 |

## 示例与合并规则

每日经营图使用订单库的销售额和广告 API 的花费。订单库按业务日汇总，广告 API 拉取同一日期范围并按日聚合。两侧统一业务时区和币种，校验每日每侧至多一行，再按日期键的并集对齐。输出字段为业务日期、销售额、广告花费和 `ROAS`。该例假设销售额采用既定的广告归因口径。若使用全站销售额，指标命名为「全站销售额 / 广告花费」。

- 缺少输入记录时对应字段为空。来源明确返回零时才记为零。分母为零或任一值缺失时，`ROAS` 为空。
- 日期范围统一采用开始日包含、结束日排除的约定。两侧聚合后的键重复时刷新失败，避免重复计入金额。
- 同结构的来源可配置 `UNION ALL`。合并前统一字段名和类型，保留来源标识，相同业务记录的去重规则由数据集契约显式定义。
- 首版图表基于已发布的粒度过滤和分组。跨天汇总 ROAS 时，分子与分母只汇总两侧金额均已知的日期。任一金额缺失的日期从两侧同时排除，仍计入所选区间的自然日总数。没有完整日期或汇总花费为零时返回空。图表同时展示完整日期数和区间总天数，例如「覆盖 5/7 天」。销售额和花费各自的汇总仍使用各列已知值。

## 刷新与权限

1. 定时任务或数据集管理页触发刷新。预览复用取数与合并校验，只返回预览结果。服务端固定本轮配置版本和取数范围，并为每个输出数据集分配单调递增的刷新启动序号。手动刷新与预览以当前成员身份执行。定时刷新绑定启用计划的空间成员，每轮取数前重新校验成员状态、输出刷新权限以及所有输入数据集和实际读取字段的权限。权限不足时记录失败并保留已有快照，计划仍可在权限恢复后继续执行。
2. 并发读取输入。数据库使用只读连接并在源端过滤、聚合。API 处理分页、超时、限流和有限重试。分页中断、字段漂移或数据超限时，本轮刷新失败。
3. 写入独立的快照存储位置，验证字段、键和完整性。随后在一个元数据事务中校验两个条件。任务配置版本必须是当前版本。若已有活动快照，本轮启动序号必须大于该快照的启动序号。通过校验后标记成功并切换指针。已被替代的任务标记为 `superseded`。配置变更时原子更新配置和字段目录，并清除活动指针，常规图表查询进入等待刷新状态。旧快照和历史结果按原快照版本和保留策略访问。同一配置下刷新失败时保留最后一次成功的快照。
4. 图表查询开始时解析并固定当前快照。查看者需要具备输出数据集及所选字段的权限，并依据该快照的不可变血缘，按查看者当前权限校验快照涉及的所有上游数据集和实际读取字段。共享看板与历史结果沿用同一规则，API Key 额外受自身授权范围限制。历史结果读取还要校验结果实际使用的输出字段。
5. 数据集管理页展示最近刷新状态及各输入的数据时点。数据覆盖水位表示来源确认完整覆盖到的排他截止时点，与取数完成时间分别记录。图表使用实际查询快照中所有必需来源的最早水位作为共同覆盖截止时点，并受本轮取数范围的结束时点限制。任一必需来源无法确认水位时，显示「覆盖截止时间未知」。刷新失败且已有快照时展示上次成功结果和失败状态，尚无成功快照时展示等待刷新状态。

## 首版交付与验收

| 交付项 | 验收条件 |
| --- | --- |
| 数据集管理 | 可以在一个空间内选择数据库数据集和 API 数据集，配置日期键和输出字段，预览后保存。跨空间输入被拒绝。 |
| 刷新任务 | 支持手动和定时刷新。用固定样本验证正常、缺日、零值、重复键、API 分页中断和重叠刷新。较早启动的任务晚完成时，当前快照仍指向较新的成功版本。刷新期间改名或删除输出字段时，旧任务无法发布，新版本首个快照发布前显示等待刷新。定时身份停用或失去字段授权后，本轮刷新失败。 |
| 图表查询 | 一张图展示销售额与广告花费，并能查询派生比率。日期筛选作用于输出数据。同一配置下刷新失败后仍可查询上一份成功结果，数据时间与实际快照一致。测试两源水位不同和任一来源水位未知的展示。测试一天只有销售额、另一天只有广告花费时，跨天 ROAS 为空且覆盖为 0/2 天。 |
| 权限与兼容性 | 缺少任一所需源字段权限时拒绝预览或查询。修改字段映射后撤销旧源字段权限，旧快照和历史结果必须拒绝访问，包括通过共享看板及 API Key 访问。单源图表和同连接关联沿用单源查询路径。 |

需要随请求实时获取最新结果时，可单独扩展后端实时执行。实时模式适用于筛选范围明确、返回量可控的查询，执行器需要限制每路超时、行数和并发。首版以可重试、可追溯的快照刷新验证业务需求。
